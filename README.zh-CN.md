# 索尼 Alpha 相机修改与扩展开发研究

[English](README.md)

本仓库讲解 **如何访问和修改机内文件、让自己的代码在相机中执行、制作原生扩展，以及实现开机从存储卡加载扩展**。

已实测目标：**索尼 α1 II / ILCE-1M2，固件 4.00**。这里发布可以复用的研究方法和已验证链路，不是某个具体摄影功能的成品发布。

## 已打通的基础链路

```text
电脑通过 MSC 连接相机
        ↓
原厂服务入口与认证
        ↓
Jiritsu 文件通道：读取、写入、独立读回验证
        ↓
精确库路径触发动态加载，在相机主程序执行自己的代码
```

在此基础上，自动加载链路也已实测：

```text
机内断电保留的配置 → 小加载器 → 开机工作进程
                                      ↓ 原生进程间通信
                                 相机主程序
                                      ↓ 原生文件系统
                                 存储卡上的扩展
                                      ↓
                                 内存中的扩展运行时
```

因此可以采用“机内安装小加载器，主体扩展放卡上”的结构。相机并不是原本就会执行卡上的任意文件；触发执行依靠经过验证的机内加载入口。更换卡上文件也需要符合加载器绑定的名称、大小、校验值和版本契约。

## 从研究到制作扩展

1. 固定机型、固件和关键 ELF 文件身份，核对处理器架构与动态加载器。
2. 验证服务通信和文件访问，先做数据读回，再做最小代码执行实验。
3. 制作与目标运行库兼容的 AArch64 共享库；用可核对的完成记录证明实际执行。
4. 识别代码所在进程。辅助进程适合触发加载，菜单和拍摄相关能力通常需要进入相机主程序，并核对线程与对象生命周期。
5. 将功能模块与启动加载器分开，再接入原生文件系统读取卡上主体。
6. 分别验证冷启动、普通 OFF/ON、息屏唤醒和回放返回，确保加载与退出流程可控。

具体摄影功能仅作为这些基础能力的验证案例。菜单重建、事件接管和资源释放还存在稳定性问题；完整功能的实现情况不作为本仓库的主线。
